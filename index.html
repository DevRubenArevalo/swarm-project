Swarm Fidelity: Where Do Local Models Break?

The break point was in the instrument, not the models.

Ruben Arevalo · Independent Researcher · source on GitHub

Read the paper (PDF) Watch the 3-minute walkthrough Code & data

The finding

Only the token budget changed

10% → 93%

qwen3.5 4B on an identical task. Same prompt, same 30-agent swarm.

We set out to find the swarm size at which small local models stop behaving like frontier agents. We did not find one. Our first harness reported one anyway — confidently, plausibly, and falsely, and characterising that is this project's contribution.

The cleanest evidence is a control that changes a single variable. Holding the model, the prompt, the task and the swarm size fixed, and moving only the per-agent token budget from 512 to 2048:

ModelCorrect @ 512 tokCorrect @ 2048 tok
qwen3.5 4B0.10 [0.03, 0.26]0.93 [0.79, 0.98]
qwen3.5 9B0.03 [0.01, 0.17]0.87 [0.70, 0.95]
deepseek-r1 14B0.13 [0.05, 0.30]0.63 [0.46, 0.78]

Brackets are Wilson 95% intervals, n=30 per cell; the 4B's two intervals are disjoint. Nothing about the task changed. Eighty-three points of apparent capability collapse were a property of one configuration value in our own code.

Three-minute walkthrough

Four artifacts, four negative controls

Each is plausible, invisible in normal operation, and independently sufficient to produce a convincing break-point curve — and each gets worse on harder tasks, not better.

  1. Silent serialization. The server ran one request at a time, so a “swarm of 60” was a queue of 60. Both standard parallelism metrics report perfect parallelism for a fully serial queue — that blindness is algebraic, so it holds for any study using them.
  2. Format-only scoring. The scorer validated response shape, not content. A confidently wrong answer scored 1.0, so the sycophancy probe could not detect sycophancy.
  3. Token truncation. At 512 tokens, 83–97% of agents exhausted the budget inside a hidden reasoning field and returned an empty string, scored as model failure rather than as no measurement at all.
  4. Difficulty confounded with swarm size. Agent k got a subtask of difficulty proportional to k, so a bigger swarm was also a harder task.

Check it yourself

Every number in the paper is re-derived from the committed raw data by one command. No GPU, no inference server, no network.

git clone https://github.com/DevRubenArevalo/swarm-project
cd swarm-project
pip install -r requirements.txt
python3 -m swarm.verify
All 42 claims verified against the committed data.

It exits non-zero if any claim fails. It checks the chain from data to claim — that the paper's numbers are the numbers in the files — not the inference runs themselves.

Read the null narrowly

Our agents never read each other's output, so no mechanism exists by which swarm size could degrade per-agent correctness beyond resource contention, which we controlled for. “No break point” means this design could not have produced one — not that local-model swarms are robust. The coordination experiment this harness makes possible is set out in §5 of the paper.

Testbed: NVIDIA DGX Spark (Blackwell GB10, 128 GB unified) · Ollama 0.40.15 · qwen3.5 4B / 9B, deepseek-r1 14B (Q4_K_M)
